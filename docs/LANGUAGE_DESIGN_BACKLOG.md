# Cvolo - отложенные решения по языку

Этот список фиксирует вопросы, которые пока не следует выдавать за реализованные возможности языка.

## Числовые преобразования и переполнение

**Решено для ближайшего изменения:** запретить неявное сужение числовых типов и несовместимые переходы между знаковыми и беззнаковыми целыми типами по таблице преобразований, близкой к C#. Например, `int source = 300; byte value = source;` должен вызывать ошибку компиляции. Преобразование `(byte)source` остаётся явным. Обычный `unsafe` не отключает проверку допустимости неявных числовых преобразований.

**Нужно решить позднее:**

- Нужны ли `checked` и `unchecked`, их аналоги или другой явный механизм проверки переполнений?
- Каким должен быть режим по умолчанию при явном сужении числа, в том числе в `unsafe`?
- Должно ли переполнение при выполнении давать исключение, завершение программы, `Result`, `Option` или иной способ обработки?
- Запрещать ли явное `(byte)300` при компиляции и как разрешать намеренное усечение константы?
- Нужны ли разные правила для констант и переменных, а также для целевых `nint` и `nuint`?
- Как обеспечить единые правила при инициализации, присваивании, передаче аргументов, возвращении значений, операциях над полями, элементами массивов и глобальными переменными?
- Как проверять переполнение при явном переводе `float` / `double` в целочисленные типы и при специальных значениях (`NaN`, бесконечность)?

## Отложенные операторы

- **`%=`** - проверить желаемую семантику и реализовать составное присваивание остатка от деления. Сейчас в актуальной грамматике есть `%`, но нет `%=`.
- **`?=`** - определить точную семантику: присвоение при определённом условии, работа с `Option` или иной механизм. Не считать синтаксис реализованным до решения.
- **Другие составные и условные операторы** - сверять с грамматикой, перечнем приоритетов, проверкой типов и генерацией кода перед добавлением в документацию.

## Перед реализацией

Согласовать спецификацию, диагностические коды и тесты на корректные и ошибочные программы. Отдельно проверить поведение C# только как точку сравнения: Cvolo не обязан копировать всю семантику C#.
